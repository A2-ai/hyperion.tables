## REVIEW ADDENDUM (survey pass, 2026-07-06)

### CONTEXT

- Codebase: `hyperion.tables` — R package (S7) producing publication-ready
  pharmacometric tables (parameter, model-comparison, run-summary) from NONMEM
  models managed by the private `hyperion`/`pharos` ecosystem; renders to gt,
  flextable, PNG, and Word.
- Primary consumers: internal pharmacometricians (A2-Ai) composing tables in
  R/Quarto pipelines; table outputs land in client-facing / regulatory-style
  reports, so numeric and footnote correctness carries elevated stakes.
- Known constraints or intentional decisions worth flagging up front: S7 object
  system throughout; `hyperion` is a private, co-developed upstream treated as
  stable `[Q10 — maintainer-confirmed]`; heavy renderer deps (flextable,
  webshot2, katex, equatags, xml2, zip) are deliberately Suggests with
  `check_suggested()` gating; PNG snapshot tests run only on local macOS — CI
  compares normalized HTML only.
- **Hard maintainer directive `[Q9]`: do not touch or edit any snapshots or
  tests in this repository.** The review is read-only with respect to `tests/`
  (including `tests/testthat/_snaps/`); findings may *describe* test-coverage
  gaps, but no pass may modify, regenerate, or delete test or snapshot files.
- Areas of specific concern: statistical footnote/column correctness
  (LRT/dOFV/df), duplicated column-visibility logic, untested docx
  post-processing. Priority: statistical correctness over rendering
  maintainability `[Q8 — maintainer-confirmed]`.

### REPO MAP

**Purpose.** `hyperion.tables` is an R package (library, no CLI/service surface)
that produces publication-ready tables from NONMEM pharmacometric models managed
by the `hyperion`/`pharos` ecosystem: parameter tables, model-comparison tables,
and run-summary tables. Output targets are `gt` (HTML-first) and `flextable`
(Word-first), with PNG (`render_to_image()`) and `.docx` (`render_to_word()`)
export. Version 0.5.0.9000, S7 object system, ~10.4k lines of R.

**Entry points** (library — the "entry points" are the exported API, all under `R/`):

- Spec constructors: `TableSpec`, `SummarySpec` (`R/spec-classes.R`),
  `CIOptions`, `ParameterNameOptions`, `SectionOptions` (`R/spec-options.R`).
- Pipeline verbs: `apply_table_spec()` (`R/parameter-apply.R:19`),
  `add_summary_info()` (`R/parameter-table.R:66`), `compare_with()` /
  `add_model_lineage()` (`R/compare.R:659,714`), `apply_summary_spec()`
  (`R/summary.R:65`).
- Table builders: `make_parameter_table()` (`R/parameter-table.R:247`),
  `make_comparison_table()` (`R/compare-table.R:433`), `make_summary_table()`
  (`R/summary.R:807`). Each accepts `output = c("gt", "flextable", "data")`.
- Renderers/exporters: `render_to_gt()` (`R/render-gt.R:12`),
  `render_to_flextable()` (`R/render-flextable.R:12`), `apply_formatting()`
  (`R/render-common.R:13`), S3 generics `render_to_image()` /
  `render_to_word()` (`R/render-common.R:349,382`) with `gt_tbl` and
  `flextable` methods.
- ~40 fluent `get_spec_*` / `set_spec_*` accessors (`R/spec-getters.R`,
  `R/spec-setters.R`); rule-builder DSL `section_rules()`, `filter_rules()`,
  `variability_rules()` (`R/spec-rules.R`), `summary_filter_rules()`
  (`R/summary.R:47`).

**Intended layering** (inferred from the `Collate` order in `DESCRIPTION`, the
`@include` directives, and the README pipeline examples):

```
spec definition   (spec-options → spec-classes → spec-rules/-validation/-setters/-getters)
      ↓
data pipeline     (parameter-apply | compare | summary)   — attaches spec to df as attribute
      ↓
intermediate rep  (hyperion-table.R: HyperionTable)
      ↓
renderers         (render-common → render-gt | render-flextable)
      ↓
export            (render_to_image / render_to_word methods)
```

`format.R` and `variability.R` are shared by both the pipeline and renderer
layers. Note one deliberate cross-layer channel: data frames carry
`hyperion_spec` / `model_summary` / `hyperion_meta` attributes downstream, and
`HyperionTable@source_spec` lets renderers reach back into the original spec.

**Most load-bearing files:**

1. `R/format.R` — statistic detection + footnote/label builders consumed by all
   three table types and both renderers.
2. `R/render-common.R` — `apply_formatting()` sits on every render path
   (gt, flextable, and the user-facing `output = "data"` escape hatch).
3. `R/spec-getters.R` `get_spec_columns()` + `R/spec-validation.R` — the column
   resolution rule `(columns %||% default) ∪ add − drop` is consulted from at
   least parameter-table, compare, compare-table, format, and variability code.

**Cross-cutting concerns:**

- **Errors:** de facto strategy is `rlang::abort()` for user/API errors at
  entry-point boundaries (S7 `S7_inherits` guards on nearly every exported
  function), `rlang::warn()` for degraded-but-continuing output (missing
  summaries, unmatched section labels), `rlang::inform()` for statistical
  suppression explanations (LRT, dOFV — `R/compare-table.R:274`,
  `R/summary.R:660`). Partial-failure tolerance in `load_models()`
  (`R/summary.R:266`): warn-and-continue per model, abort only if all fail.
- **Config:** no env/config files of its own; all configuration flows through
  spec objects. Exceptions: `hyperion.config_dir` option (set in test
  `setup.R`, consumed inside `hyperion::from_config_relative`), and
  `QUARTO_BIN_PATH` env var temporarily unset in `render_to_image.gt_tbl`
  (`R/render-gt.R:359`).
- **Validation:** S7 validators on all spec classes plus column-vocabulary
  checks (`R/spec-validation.R`). Untrusted input enters from model files via
  `hyperion::read_model()` / `summary()` — guarded by `tryCatch` +
  `safe_summary_field()` (`R/utils.R:90`).
- **Logging:** none beyond R conditions.
- **Concurrency:** none (pure single-threaded transforms).
- **Suggested-package gating:** `check_suggested()` (`R/utils.R:23`) with
  abort/warn severities; heavy features (flextable, webshot2, katex, equatags,
  xml2, zip) are all Suggests.

**Build/test/CI:** standard roxygen2 package; dependencies managed with `rv`
(`rproject.toml`), hyperion is a private GitHub dependency (CI injects a
`PRIVATE_REPO_ACCESS_TOKEN`). Tests: testthat edition 3, ~4.2k lines — heavy
end-to-end snapshot coverage of all three table types (normalized HTML always;
PNG snapshots deliberately `skip_on_ci`/skip-on-linux/windows, so CI compares
HTML only). CI: GitHub Actions R-CMD-check matrix (macOS + ubuntu, R 4.2–4.5)
plus a release workflow. Docs site built with starlightr (`_starlightr.toml`).

`inst/extdata/models/` were only skimmed — re-verify anything relied on there.
