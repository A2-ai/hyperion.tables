## REVIEW ADDENDUM (survey pass, 2026-07-06)

### CONTEXT

- Codebase: `hyperion.tables` — R package producing publication-ready parameter,
  model-comparison, and run-summary tables (gt / flextable / PNG / Word) from
  NONMEM models managed by the upstream `hyperion`/`pharos` toolchain.
- Primary consumers: internal pharmacometricians at A2-Ai producing
  client-facing and regulatory-adjacent report deliverables; tables are the
  end product, so silent numerical/formatting errors reach humans directly.
- Known constraints or intentional decisions worth flagging up front: dual
  render backends (gt + flextable) are both first-class `[Q2]`; the package
  leans on data.frame attributes for inter-stage state by design (see
  `R/df-attrs.R:33-35`); upstream `hyperion` is same-team, released in
  lockstep, and pinned via rv (`rproject.toml`) `[Q5]` `[Q10]`; LRT/dOFV
  functionality is slated to move to pharos and be reworked there `[Q1]`;
  manipulating the data frames between `apply_*` and `make_*` stages is not a
  supported user flow — users manipulate before `apply_*` or via the spec
  `[Q4]`.
- Areas of specific concern: both statistical/numerical correctness of table
  output and maintainability of the render layer matter equally (maintainer
  answer `[Q9]`); the untested Word/OOXML export path `[Q3]`.

### PRIORITY TARGETS

Allocate ~80% of investigation here, in order.

**T1 — gt/flextable backend drift and the trifurcated LaTeX handling (from H2,
confidence high) `[Q2]`**
Parallel unshared helper pairs: labels `R/render-gt.R:136` /
`R/render-flextable.R:227`; spanners `:172`/`:266`; bold `:185`/`:313`; borders
`:220`/`:350`; footnotes `:236`/`:401`; title `:161`/`:332`. LaTeX exists three
times: gt HTML (`gt::md()`/katex), gt docx (`rewrite_latex_to_omml`,
`R/render-gt.R:883`), flextable hand-rolled (`convert_md_label`
`R/render-flextable.R:249`, `parse_subscripts_to_chunks` `:561`).
Investigate: render one feature-rich table (sections + spanners + borders +
`$...$` labels/footnotes + CI merge + missing-text) through both backends and
diff semantics; check the three hard-coded full-formula `gsub` patterns at
`R/render-flextable.R:509-524` against the footnote strings actually emitted by
`R/format.R` (`build_equations_footnote`) and `R/compare-table.R`
(`format_ofv_lrt_footnote`) for drift that has already happened.

**T2 — Untested Word/image export path and OOXML surgery (from H3, confidence
high) `[Q3]` `[Q8]`**
`render_to_word`/`render_to_image` have zero test references; the docx pipeline
is ~15 helpers of raw xml2/zip surgery (`sanitize_gt_docx` suite,
`R/render-gt.R:402-1052`) keyed to OOXML shapes the installed gt version emits
(`<w:tblHeader/>`/gridSpan walking, `R/render-gt.R:591-605`); `QUARTO_BIN_PATH`
is unset/restored around katex (`R/render-gt.R:359-363`).
Investigate: failure modes on gt/officer/equatags version drift; tempfile/zip
partial-failure handling; whether the env-var restore survives error paths
(`on.exit` or not); actually run `render_to_word` on fixture tables for both
backends and inspect output.

**T3 — Internal attribute save/restore fragility across pipeline stages (from
H4, narrowed per `[Q4]`)**
State attrs: `hyperion_spec`, `model_summary`, `hyperion_meta`,
`summary_time_unit`, `.needs_dofv` (`R/df-attrs.R`). Hand save/restore:
`capture_comparison_attrs`/`restore_comparison_attrs` (`R/compare.R:12-30`)
around selects at `R/compare-table.R:479-490,1100-1149`; manual
`summary_time_unit` round-trip at `R/summary.R:114-118`. Spec loss is loud
(`get_table_spec` aborts, `R/parameter-table.R:123`) but `model_summary` loss is
silent (`R/parameter-table.R:8`).
Scope note `[Q4]`: users running dplyr verbs between `apply_*` and `make_*` is
NOT a supported flow — do not report user-pipeline attribute loss as a finding.
The target is *internal* correctness: enumerate every dplyr/base verb the
package itself applies between attach and read points in all three pipelines
and check which attrs survive; look for a missing restore pair in `R/summary.R`
around `filter_unrun_rows`/`format_time_columns`; check whether any
`vignettes/*.Rmd` example demonstrates the unsupported between-stage
manipulation (that would be a doc defect, not an architecture finding).

**T4 — Column-name convention sprawl as the real inter-stage contract (from H6,
confidence medium-high)**
Suffix regexes `"^(...)_(\\d+)$"` at ~a dozen sites (`R/compare.R:33`,
`R/compare-table.R:746,859`, others); internal-column lists re-listed at
`R/parameter-table.R:150` vs `R/compare-table.R:745`; symbol/fixed/CI column
regexes at `R/render-flextable.R:131`, `R/format.R:86,220`; two independent
CI-alias lists (`expand_ci_alias` `R/spec-validation.R:76` vs
`expand_ci_drop_columns` `R/spec-validation.R:99`). Prior art: NEWS 0.5.0
records a released column-dropping bug of exactly this class (`NEWS.md:45`).
Investigate: build the cross-reference table of every site encoding the suffix
scheme or internal-column vocabulary; check `comparison_suffix_columns()`
against what `compare_with` actually suffixes; probe with a model having extra
`dt_*` columns.

**T5 — Numeric formatting correctness (promoted from open hunt per `[Q9]`:
correctness and maintainability both matter)**
The sigfig/rounding pathway is spread across `format_sigfig_pad`/
`format_numeric_for_rules` (`R/variability.R`), `format_value`/
`format_numeric_columns_shared` (`R/render-common.R`), and
`hyperion::format_hyperion_decimal_string`/`format_hyperion_sigfig_string` call

Investigate: edge cases (0, negatives, values crossing the sigfig/decimal
boundary, very large/small magnitudes, NA) for consistency across the three
formatting entry points; whether the same number can format differently in a
parameter table vs the same model's column in a comparison table; p-value
formatting/threshold interplay (`format_pvalue_string`, `R/utils.R:121`).

#### Purpose and type

`hyperion.tables` is an R package (shared library, no executables) that produces
publication-ready tables — parameter tables, model comparison tables, and run
summary tables — from NONMEM pharmacometric models managed by the upstream
`hyperion`/`pharos` toolchain (both A2-Ai internal). Output targets are `gt` and
`flextable` table objects, exportable to PNG and Word (`.docx`). Version
0.5.0.9000, ~10.4k lines of R across 22 files, repo started 2026-01-23
(~6 months old, 167 commits).

#### Entry points (exported API; no mains/routes/workers)

Three data pipelines, each `apply → (enrich) → make_* → render`:

- **Parameter pipeline**: `apply_table_spec()` (`R/parameter-apply.R:1`) →
  `add_summary_info()`, `make_parameter_table()`, `get_table_spec()`
  (`R/parameter-table.R`).
- **Comparison pipeline**: `compare_with()`, `add_model_lineage()`
  (`R/compare.R`) → `make_comparison_table()` (`R/compare-table.R:432`).
- **Summary pipeline**: `apply_summary_spec()`, `make_summary_table()`,
  `get_summary_spec()`, `summary_filter_rules()` (`R/summary.R`).
- **Rendering**: `render_to_gt()` (`R/render-gt.R:12`), `render_to_flextable()`
  (`R/render-flextable.R:12`), shared preprocessing `apply_formatting()` plus
  S3 generics `render_to_image()`/`render_to_word()` (`R/render-common.R:13,349,382`)
  with backend methods in the two render files.
- **Spec construction**: `TableSpec`/`SummarySpec` S7 classes
  (`R/spec-classes.R:194,503`), option classes `CIOptions`/`ParameterNameOptions`/
  `SectionOptions` (`R/spec-options.R:24,121,170`), ~20 `set_spec_*` setters
  (`R/spec-setters.R`) and ~20 `get_spec_*` getters (`R/spec-getters.R`),
  rule DSLs `section_rules()`/`filter_rules()`/`variability_rules()`
  (`R/spec-rules.R`).
- **Load hook**: `.onLoad` → `S7::methods_register()` (`R/zzz.R`).

NAMESPACE: 67 exports, 6 S3 methods (`render_to_image`/`render_to_word` ×
default/gt_tbl/flextable).

#### Intended layering (inferred)

specs (S7 value objects) → pipeline stage 1 (`apply_*`: plain data.frame + spec
carried in attributes) → pipeline stage 2 (`make_*`: build `HyperionTable` IR) →
backend renderers (`render_to_gt`/`render_to_flextable`) → exporters
(`render_to_image`/`render_to_word`). Inferred from the `Collate:` order in
`DESCRIPTION`, `@include` directives (`R/hyperion-table.R:1`), and the
`HyperionTable` doc comment ("Captures all styling intent in a format-agnostic
way", `R/hyperion-table.R:8-11`). The IR boundary is mostly respected; the main
leak is gt-specific docx state stashed as
`attr(gt_table, "hyperion_segment_lengths")` (`R/render-gt.R:82`, read back at
`R/render-gt.R:409`).

#### Most load-bearing files

1. `R/render-common.R` — `apply_formatting()` sits on every render path for all
   three table types; also owns the export generics.
2. `R/hyperion-table.R` — the IR class every `make_*` produces and both backends
   consume; its property list is the de facto renderer contract.
3. `R/spec-classes.R` — every pipeline call consumes a `TableSpec`/`SummarySpec`;
   validators here gate all user configuration.

#### Cross-cutting concerns

- **Errors**: rlang throughout. De facto strategy: `abort` on spec-type
  mismatch, missing spec at `make_*` time, and empty results
  (`R/parameter-table.R:260`, `R/summary.R:76,283`, `R/compare-table.R:406-411`,
  `R/compare.R:258`); `warn`-and-continue for per-model failures in the summary
  pipeline (`R/summary.R:277-294`, back-fills NA rows); `inform` for statistical
  suppression (`R/compare-table.R:274`, `R/summary.R:660`). Suggests-gating via
  `check_suggested()` (`R/utils.R:23`) with mixed abort/warn severities.
- **Config**: no package-level options. `getOption("knitr.in.progress")` read in
  both image renderers (`R/render-gt.R:351`, `R/render-flextable.R:662`);
  `QUARTO_BIN_PATH` env var unset/restored around katex rendering
  (`R/render-gt.R:359-363`); path resolution delegated to
  `hyperion::from_config_relative` (`R/compare.R:137`, `R/summary.R:271`); tests
  set `options(hyperion.config_dir = ...)` (`tests/testthat/setup.R`).
- **Logging**: none (only rlang conditions).
- **Validation**: three layers — S7 validators embedded in classes
  (`R/spec-classes.R:70,249,550`; `R/spec-options.R`), free-function helpers
  (`R/spec-validation.R`), and imperative constructor checks plus
  friendly-error translation in setters (`R/spec-setters.R:442-489`).
- **Concurrency**: none; pure single-threaded data transformation.
- **Inter-stage state**: data.frame attributes — `hyperion_spec`,
  `model_summary`, `.needs_dofv`, `summary_time_unit`, `hyperion_meta`
  (partially centralized in `R/df-attrs.R`; hand save/restore around dplyr verbs
  at `R/compare.R:12-30` and `R/summary.R:114-118`).
