## 1. Repository map

**Purpose.** `hyperion.tables` is an R package (library, no CLI/service surface)
that produces publication-ready tables from NONMEM pharmacometric models managed
by the `hyperion`/`pharos` ecosystem: parameter tables, model-comparison tables,
and run-summary tables. Output targets are `gt` (HTML-first) and `flextable`
(Word-first), with PNG (`render_to_image()`) and `.docx` (`render_to_word()`)
export. Version 0.5.0.9000, S7 object system, ~10.4k lines of R.

**Entry points** (library — the "entry points" are the exported API, all under `R/`):

- Spec constructors: `TableSpec`, `SummarySpec` (`R/spec-classes.R`),
  `CIOptions`, `ParameterNameOptions`, `SectionOptions` (`R/spec-options.R`).
- Pipeline verbs: `apply_table_spec()` (`R/parameter-apply.R:19`),
  `add_summary_info()` (`R/parameter-table.R:66`), `compare_with()` /
  `add_model_lineage()` (`R/compare.R:659,714`), `apply_summary_spec()`
  (`R/summary.R:65`).
- Table builders: `make_parameter_table()` (`R/parameter-table.R:247`),
  `make_comparison_table()` (`R/compare-table.R:433`), `make_summary_table()`
  (`R/summary.R:807`). Each accepts `output = c("gt", "flextable", "data")`.
- Renderers/exporters: `render_to_gt()` (`R/render-gt.R:12`),
  `render_to_flextable()` (`R/render-flextable.R:12`), `apply_formatting()`
  (`R/render-common.R:13`), S3 generics `render_to_image()` /
  `render_to_word()` (`R/render-common.R:349,382`) with `gt_tbl` and
  `flextable` methods.
- ~40 fluent `get_spec_*` / `set_spec_*` accessors (`R/spec-getters.R`,
  `R/spec-setters.R`); rule-builder DSL `section_rules()`, `filter_rules()`,
  `variability_rules()` (`R/spec-rules.R`), `summary_filter_rules()`
  (`R/summary.R:47`).

**Intended layering** (inferred from the `Collate` order in `DESCRIPTION`, the
`@include` directives, and the README pipeline examples):

```
spec definition   (spec-options → spec-classes → spec-rules/-validation/-setters/-getters)
      ↓
data pipeline     (parameter-apply | compare | summary)   — attaches spec to df as attribute
      ↓
intermediate rep  (hyperion-table.R: HyperionTable)
      ↓
renderers         (render-common → render-gt | render-flextable)
      ↓
export            (render_to_image / render_to_word methods)
```

`format.R` and `variability.R` are shared by both the pipeline and renderer
layers. Note one deliberate cross-layer channel: data frames carry
`hyperion_spec` / `model_summary` / `hyperion_meta` attributes downstream, and
`HyperionTable@source_spec` lets renderers reach back into the original spec.

**Most load-bearing files:**

1. `R/format.R` — statistic detection + footnote/label builders consumed by all
   three table types and both renderers.
2. `R/render-common.R` — `apply_formatting()` sits on every render path
   (gt, flextable, and the user-facing `output = "data"` escape hatch).
3. `R/spec-getters.R` `get_spec_columns()` + `R/spec-validation.R` — the column
   resolution rule `(columns %||% default) ∪ add − drop` is consulted from at
   least parameter-table, compare, compare-table, format, and variability code.

**Cross-cutting concerns:**

- **Errors:** de facto strategy is `rlang::abort()` for user/API errors at
  entry-point boundaries (S7 `S7_inherits` guards on nearly every exported
  function), `rlang::warn()` for degraded-but-continuing output (missing
  summaries, unmatched section labels), `rlang::inform()` for statistical
  suppression explanations (LRT, dOFV — `R/compare-table.R:274`,
  `R/summary.R:660`). Partial-failure tolerance in `load_models()`
  (`R/summary.R:266`): warn-and-continue per model, abort only if all fail.
- **Config:** no env/config files of its own; all configuration flows through
  spec objects. Exceptions: `hyperion.config_dir` option (set in test
  `setup.R`, consumed inside `hyperion::from_config_relative`), and
  `QUARTO_BIN_PATH` env var temporarily unset in `render_to_image.gt_tbl`
  (`R/render-gt.R:359`).
- **Validation:** S7 validators on all spec classes plus column-vocabulary
  checks (`R/spec-validation.R`). Untrusted input enters from model files via
  `hyperion::read_model()` / `summary()` — guarded by `tryCatch` +
  `safe_summary_field()` (`R/utils.R:90`).
- **Logging:** none beyond R conditions.
- **Concurrency:** none (pure single-threaded transforms).
- **Suggested-package gating:** `check_suggested()` (`R/utils.R:23`) with
  abort/warn severities; heavy features (flextable, webshot2, katex, equatags,
  xml2, zip) are all Suggests.

**Build/test/CI:** standard roxygen2 package; dependencies managed with `rv`
(`rproject.toml`), hyperion is a private GitHub dependency (CI injects a
`PRIVATE_REPO_ACCESS_TOKEN`). Tests: testthat edition 3, ~4.2k lines — heavy
end-to-end snapshot coverage of all three table types (normalized HTML always;
PNG snapshots deliberately `skip_on_ci`/skip-on-linux/windows, so CI compares
HTML only). CI: GitHub Actions R-CMD-check matrix (macOS + ubuntu, R 4.2–4.5)
plus a release workflow. Docs site built with starlightr (`_starlightr.toml`).

## 2. Risk hypotheses (ranked, max 8)

### H1 — Column-visibility policy is implemented twice (parameter vs comparison) and has already drifted

- **Hypothesis:** `resolve_hidden_columns()` (`R/parameter-table.R:428-509`)
  and `compute_comparison_layout()` (`R/compare-table.R:725-939`) are
  independent implementations of the same "requested ∪ add − drop − empty,
  with special cases for fixed/ci/variability/pct_change" policy, and they
  disagree in edge cases.
- **Signal:** both files re-derive `fixed_requested`, empty-column exemption,
  ci-pair collapsing, and variability/component mutual exclusion with different
  code shapes (set arithmetic vs regex over `_\d+$` suffixes).
  `compute_comparison_layout` alone is ~215 lines of accreted hide rules with
  five near-identical `hide_suffix <- hide_suffix[!grepl(...)]` blocks. NEWS
  0.5.0 records a bug fixed in exactly this area ("no longer drops columns when
  an added model lacks columns present on the reference model"), i.e., drift
  has fired before. A third partial copy of the same resolution lives in
  `detect_table_statistics()` (`R/format.R:190-201`).
- **If true, cost:** every new column or display option must be implemented in
  2–3 places with no mechanism forcing sync; user-visible symptoms are columns
  silently appearing/disappearing depending on table type. Change amplification
  on the package's most-touched axis.
- **Investigation sketch:** build a matrix of spec configurations
  (columns/add/drop × fixed × ci merge × hide_empty × variability) and trace
  which columns each path shows; diff `resolve_hidden_columns` vs
  `compute_comparison_layout` decision-by-decision; check whether
  `ci_high` collapse and `fixed_fmt` swap rules match. Grep for
  `fixed_requested` and `hide_empty_columns` to enumerate all copies.
- **Confidence:** high.

### H2 — LRT/dOFV statistics are computed by two independent implementations with different df definitions

- **Hypothesis:** the comparison-table path and the summary-table path compute
  the same likelihood-ratio test with different degrees-of-freedom sources and
  different gating, so the same model pair can show different df/p-values (or
  one path shows a p-value the other suppresses).
- **Signal:** comparison path: `can_show_lrt()` (`R/compare.R:91-144`) + a
  *second, partially duplicated* check inside `format_ofv_lrt_footnote()`
  (`R/compare-table.R:233-287`) compute
  `df = |Σ(!fixed) − Σ(!fixed)|` from the joined table's `fixed_N` columns and
  require lineage via `are_models_in_lineage()`. Summary path:
  `calculate_dofv()` (`R/summary.R:616-701`) computes
  `df = n_parameters(model) − n_parameters(parent)` from
  `summary()$parameters` and gates only on `based_on` + matching nobs — no
  lineage-file check. Non-fixed rows in a joined comparison ≠ non-fixed
  parameters in a model summary whenever the join drops/merges rows.
- **If true, cost:** wrong or inconsistent statistical output in a
  pharmacometric reporting tool — the highest-stakes correctness surface in the
  package (these tables go into regulatory-style reports).
- **Investigation sketch:** with the bundled `inst/extdata/models/onecmt` runs,
  produce a comparison table and a summary table for the same parent/child pair
  and compare df/p-value. Read `format_ofv_lrt_footnote` and note that it
  recomputes df and nobs equality *before* calling `can_show_lrt` (which redoes
  both) — check the two stay consistent. Also verify sign conventions:
  `lrt_pvalue(-delta_ofv, df)` in both paths (`R/compare-table.R:254`,
  `R/summary.R:689`).
- **Confidence:** high (that duplication exists); medium (that they numerically
  disagree on realistic data).

### H3 — Pipeline state rides on data-frame attributes preserved by convention, not mechanism

- **Hypothesis:** the user-facing pipeline
  (`get_parameters() |> apply_table_spec() |> add_summary_info() |> compare_with()`)
  silently loses its state (`hyperion_spec`, `model_summary`, `hyperion_meta`,
  class `hyperion_comparison`, `.needs_dofv`, `summary_time_unit`) if the user
  interposes any dplyr verb, and internally the package must remember to
  capture/restore around its own dplyr calls.
- **Signal:** `R/df-attrs.R` centralizes the attrs; `R/compare.R:12-29`
  (`capture_comparison_attrs`/`restore_comparison_attrs`) exist precisely
  because "dplyr operations strip attributes", and are invoked at
  `R/compare-table.R:479/490` and `:1100/1149` — but nothing protects the
  *user's* interstitial `filter()`/`mutate()` (README markets this as a
  composable pipe). Failure modes are asymmetric: lost spec → hard abort later
  ("TableSpec not found"), lost `model_summary` → footnotes silently vanish
  with only a warning at compare time, lost `hyperion_meta` labels →
  regenerated as "Model 1/2" fallbacks (`normalize_comparison_meta`,
  `R/compare.R:44-54`).
- **If true, cost:** a class of confusing user bugs ("my footnotes
  disappeared", "labels reset") with no error pointing at the cause; internal
  tax of remembering capture/restore at every new dplyr call site.
- **Investigation sketch:** trace attribute lifecycle across each pipeline
  stage; test `apply_table_spec(...) |> dplyr::filter(kind == "THETA") |> make_parameter_table()`
  and the comparison equivalent; enumerate internal dplyr call sites lacking
  capture/restore (e.g., `apply_summary_spec`'s `dplyr::select` chain preserves
  `summary_time_unit` by hand at `R/summary.R:114-118` — check others).
- **Confidence:** high (mechanism is factual); medium (severity depends on how
  users actually compose pipes).

### H4 — The gt and flextable renderers re-implement presentation semantics independently, coupled by exact-string contracts

- **Hypothesis:** `render-gt.R` and `render-flextable.R` are two hand-kept
  implementations of `HyperionTable`'s styling intent, and the flextable side
  additionally depends on the *exact LaTeX strings* produced by footnote
  builders in `format.R`, so edits to footnote text silently break flextable
  rendering while gt keeps working.
- **Signal:** `build_footnote_paragraph()` (`R/render-flextable.R:502-554`)
  pattern-matches hard-coded regexes for specific formulas (e.g. the full
  `\\$\\\\frac\\{\\\\mathrm\\{Estimate\\}_...` % Change formula) that must
  byte-match strings assembled in `build_equations_footnote()`
  (`R/format.R:274-366`). Column labels: gt path wraps `$...$` in `gt::md()`
  (`R/render-gt.R:149-156`), flextable path strips them via `convert_md_label()`
  (`R/render-flextable.R:249-257`) handling only `\Delta`/`\delta`. Spanner,
  border, and bold semantics are re-derived per renderer.
- **If true, cost:** cross-format visual drift (the package's whole value
  proposition is format-agnostic tables); any footnote wording change is a
  two-file, three-function edit with no test forcing parity (PNG snapshots
  don't run on CI).
- **Investigation sketch:** diff the two `apply_*` pipelines feature-by-feature
  against `HyperionTable`'s property list; mutate one equation string in
  `format.R` and observe which renderer degrades; check `has_equations`
  fallback path (`R/render-flextable.R:401-434`) against every string
  `build_equations_footnote` can emit.
- **Confidence:** high.

### H5 — The ~600-line docx XML-surgery pipeline has zero test coverage and depends on unstable gt/pandoc emission details

- **Hypothesis:** `render_to_word.gt_tbl` → `sanitize_gt_docx()`
  (`R/render-gt.R:402-1052`) — twelve ordered XML fix-up passes (caption-style
  case, border stripping/re-adding, SEQ-field removal, header bolding, empty
  cells, tblGrid injection, XSD reordering, LaTeX→OMML rewrite, xmlns dedup on
  serialized bytes, compat mode) — will break silently on a gt or pandoc
  upgrade, and nothing in CI would notice.
- **Signal:** `grep -rl render_to_word tests/` returns nothing; each helper's
  comment documents a reverse-engineered gt/pandoc emission quirk ("gt emits
  <w:pStyle w:val='caption'/> but…", "Pandoc's docx backend…"), i.e., the code
  is a mirror of a specific upstream version's output. DESCRIPTION pins
  `gt (>= 1.0.0)` — a floor, not a version.
- **If true, cost:** Word deliverables (the flagship 0.5.0 feature per NEWS)
  corrupt or regress to "unreadable content" prompts on dependency updates,
  discovered by end users rather than CI.
- **Investigation sketch:** confirm zero coverage; assess which passes are
  load-bearing vs cosmetic; check whether a minimal round-trip test (render →
  save → unzip → assert well-formed XML + key invariants like tblGrid presence,
  no fldChar) is feasible in CI without Word; evaluate `dedupe_xmlns_w`'s raw
  string surgery (`R/render-gt.R:954-965`) for false-positive replacements
  inside attribute values.
- **Confidence:** high (coverage gap is verified); medium (imminence of
  breakage).

### H6 — A dead legacy rendering chain looks alive

- **Hypothesis:** the pre-`HyperionTable` gt rendering path survives as
  uncalled code that will silently drift from the live path.
- **Signal:** `render_gt_comparison_table` (`R/compare-table.R:534-556`),
  `render_gt_summary_table` (`R/summary.R:846-849`), `apply_model_spanners`
  (`R/compare-table.R:1046`), `apply_comparison_footnotes`
  (`R/compare-table.R:1060`) → `add_conditional_footnotes`
  (`R/render-gt.R:304`) → `add_footnotes` (`R/render-gt.R:257`), and
  `convert_footnote_to_text` (`R/render-flextable.R:607`) have **no callers**
  outside this chain (verified by grep across `R/` and `tests/`); two carry
  comments claiming they "preserve the original gt rendering logic for
  backwards compatibility" yet are `@noRd` internals.
- **If true, cost:** ~250 lines of shadow logic that reviewers/maintainers keep
  in sync for nothing (the `add_conditional_footnotes` chain re-implements
  `build_*_footnotes`), plus misleading "backwards compatibility" comments.
- **Investigation sketch:** confirm reachability with a call graph; check git
  history for when `hyperion_*_table()` constructors superseded them; verify
  deleting them passes R CMD check + tests.
- **Confidence:** high (they are uncalled); low risk of being wrong.

### H7 — Dynamic section labels are half-supported: the validator tolerates them, the rendering path crashes on them

- **Hypothesis:** section rules whose RHS is not a string literal (e.g.
  `kind == "THETA" ~ my_label_var`) pass `SectionOptions` validation — which
  contains elaborate machinery to resolve or tolerate dynamic labels — but
  crash or misbehave in `get_section_order()` / `build_summary_section()`.
- **Signal:** the validator (`R/spec-options.R:282-353`) `eval_tidy`s
  non-literal RHS and downgrades unknown-label errors to warnings when
  `any_dynamic` — clear intent to allow them. But `get_section_order()`
  (`R/parameter-apply.R:424-432`) does
  `vapply(rules, function(rule) rlang::f_rhs(rlang::eval_tidy(rule)), character(1))`
  — `f_rhs()` returns the unevaluated RHS *expression*, so a symbol/call RHS
  fails the `character(1)` check and aborts. Same pattern in
  `build_summary_section()` (`R/summary.R:380`) and
  `warn_multi_match_sections()` (`R/parameter-apply.R:365`).
- **If true, cost:** a documented-looking feature (formulas "following
  `dplyr::case_when()` syntax", which allows computed RHS) that works at spec
  build time and explodes at table build time with an opaque vapply error.
- **Investigation sketch:** construct
  `lbl <- "X"; TableSpec() |> set_spec_sections(kind == "THETA" ~ lbl)` and
  run `apply_table_spec` + `make_parameter_table`; also test
  `~ paste("A", "B")`. Decide whether the fix is resolve-early (normalize
  labels at setter time, where the validator already has the logic) or
  document-literal-only.
- **Confidence:** medium-high.

### H8 — `hide_empty_columns` / statistic detection interact with formatting order to produce inconsistent footnotes

- **Hypothesis:** footnote/abbreviation detection (`detect_table_statistics`,
  `R/format.R:186-261`) evaluates the *pre-formatting* data with its own copy
  of column-resolution logic, so footnotes can reference columns that the
  hide/empty logic later removes, or miss statistics present only in model
  indices ≥ 3.
- **Signal:** `has_rse_comparison` hard-codes `rse_1`/`rse_2`
  (`R/format.R:227-228`) while `has_ci` scans all `ci_(low|high)*` columns —
  a 3-model chain with RSE only in model 3 misses the RSE abbreviation; the
  `spec`-based suppression at `R/format.R:190-201` re-derives effective columns
  independently of `resolve_hidden_columns` (ties into H1) and doesn't know
  about empty-column hiding.
- **If true, cost:** wrong/missing abbreviation & equation footnotes —
  cosmetic-to-embarrassing in report deliverables; low blast radius but very
  visible.
- **Investigation sketch:** 3-model chained comparison where only the newest
  model has RSE/CI populated; a table where `hide_empty_columns` removes the
  only CI columns — check whether the CI equation footnote still prints.
- **Confidence:** medium.

## REVIEW ADDENDUM (survey pass, 2026-07-06)

### CONTEXT

- Codebase: `hyperion.tables` — R package (S7) producing publication-ready
  pharmacometric tables (parameter, model-comparison, run-summary) from NONMEM
  models managed by the private `hyperion`/`pharos` ecosystem; renders to gt,
  flextable, PNG, and Word.
- Primary consumers: internal pharmacometricians (A2-Ai) composing tables in
  R/Quarto pipelines; table outputs land in client-facing / regulatory-style
  reports, so numeric and footnote correctness carries elevated stakes.
- Known constraints or intentional decisions worth flagging up front: S7 object
  system throughout; `hyperion` is a private, co-developed upstream treated as
  stable `[Q10 — maintainer-confirmed]`; heavy renderer deps (flextable,
  webshot2, katex, equatags, xml2, zip) are deliberately Suggests with
  `check_suggested()` gating; PNG snapshot tests run only on local macOS — CI
  compares normalized HTML only.
- **Hard maintainer directive `[Q9]`: do not touch or edit any snapshots or
  tests in this repository.** The review is read-only with respect to `tests/`
  (including `tests/testthat/_snaps/`); findings may *describe* test-coverage
  gaps, but no pass may modify, regenerate, or delete test or snapshot files.
- Areas of specific concern: statistical footnote/column correctness
  (LRT/dOFV/df), duplicated column-visibility logic, untested docx
  post-processing. Priority: statistical correctness over rendering
  maintainability `[Q8 — maintainer-confirmed]`.
- Maintainer answers received 2026-07-10: Q1–Q8 and Q10 confirmed at their
  stated defaults; Q9 answered with the directive above. All `[Q#]` markers in
  this addendum are therefore resolved — treat each referenced default as
  maintainer-confirmed.

### PRIORITY TARGETS

Allocate ~80% of investigation here, ordered by expected value. Each is a

### REPO MAP

**Purpose.** `hyperion.tables` is an R package (library, no CLI/service surface)
that produces publication-ready tables from NONMEM pharmacometric models managed
by the `hyperion`/`pharos` ecosystem: parameter tables, model-comparison tables,
and run-summary tables. Output targets are `gt` (HTML-first) and `flextable`
(Word-first), with PNG (`render_to_image()`) and `.docx` (`render_to_word()`)
export. Version 0.5.0.9000, S7 object system, ~10.4k lines of R.

**Entry points** (library — the "entry points" are the exported API, all under `R/`):

- Spec constructors: `TableSpec`, `SummarySpec` (`R/spec-classes.R`),
  `CIOptions`, `ParameterNameOptions`, `SectionOptions` (`R/spec-options.R`).
- Pipeline verbs: `apply_table_spec()` (`R/parameter-apply.R:19`),
  `add_summary_info()` (`R/parameter-table.R:66`), `compare_with()` /
  `add_model_lineage()` (`R/compare.R:659,714`), `apply_summary_spec()`
  (`R/summary.R:65`).
- Table builders: `make_parameter_table()` (`R/parameter-table.R:247`),
  `make_comparison_table()` (`R/compare-table.R:433`), `make_summary_table()`
  (`R/summary.R:807`). Each accepts `output = c("gt", "flextable", "data")`.
- Renderers/exporters: `render_to_gt()` (`R/render-gt.R:12`),
  `render_to_flextable()` (`R/render-flextable.R:12`), `apply_formatting()`
  (`R/render-common.R:13`), S3 generics `render_to_image()` /
  `render_to_word()` (`R/render-common.R:349,382`) with `gt_tbl` and

**Intended layering** (inferred from the `Collate` order in `DESCRIPTION`, the
`@include` directives, and the README pipeline examples):

```
spec definition   (spec-options → spec-classes → spec-rules/-validation/-setters/-getters)
      ↓
data pipeline     (parameter-apply | compare | summary)   — attaches spec to df as attribute
      ↓
intermediate rep  (hyperion-table.R: HyperionTable)
      ↓
renderers         (render-common → render-gt | render-flextable)
      ↓
export            (render_to_image / render_to_word methods)
```

`format.R` and `variability.R` are shared by both the pipeline and renderer
layers. Note one deliberate cross-layer channel: data frames carry
`hyperion_spec` / `model_summary` / `hyperion_meta` attributes downstream, and
`HyperionTable@source_spec` lets renderers reach back into the original spec.

**Most load-bearing files:**

1. `R/format.R` — statistic detection + footnote/label builders consumed by all
   three table types and both renderers.
2. `R/render-common.R` — `apply_formatting()` sits on every render path
   (gt, flextable, and the user-facing `output = "data"` escape hatch).
3. `R/spec-getters.R` `get_spec_columns()` + `R/spec-validation.R` — the column
   resolution rule `(columns %||% default) ∪ add − drop` is consulted from at
   least parameter-table, compare, compare-table, format, and variability code.

**Cross-cutting concerns:**

- **Errors:** de facto strategy is `rlang::abort()` for user/API errors at
  entry-point boundaries (S7 `S7_inherits` guards on nearly every exported
  function), `rlang::warn()` for degraded-but-continuing output (missing
  summaries, unmatched section labels), `rlang::inform()` for statistical
  suppression explanations (LRT, dOFV — `R/compare-table.R:274`,
  `R/summary.R:660`). Partial-failure tolerance in `load_models()`
  (`R/summary.R:266`): warn-and-continue per model, abort only if all fail.
- **Config:** no env/config files of its own; all configuration flows through
  spec objects. Exceptions: `hyperion.config_dir` option (set in test
  `setup.R`, consumed inside `hyperion::from_config_relative`), and
  `QUARTO_BIN_PATH` env var temporarily unset in `render_to_image.gt_tbl`
  (`R/render-gt.R:359`).
- **Validation:** S7 validators on all spec classes plus column-vocabulary
  checks (`R/spec-validation.R`). Untrusted input enters from model files via
  `hyperion::read_model()` / `summary()` — guarded by `tryCatch` +
  `safe_summary_field()` (`R/utils.R:90`).
- **Logging:** none beyond R conditions.
- **Concurrency:** none (pure single-threaded transforms).
- **Suggested-package gating:** `check_suggested()` (`R/utils.R:23`) with
  abort/warn severities; heavy features (flextable, webshot2, katex, equatags,
  xml2, zip) are all Suggests.

**Build/test/CI:** standard roxygen2 package; dependencies managed with `rv`
(`rproject.toml`), hyperion is a private GitHub dependency (CI injects a
`PRIVATE_REPO_ACCESS_TOKEN`). Tests: testthat edition 3, ~4.2k lines — heavy
end-to-end snapshot coverage of all three table types (normalized HTML always;
PNG snapshots deliberately `skip_on_ci`/skip-on-linux/windows, so CI compares
HTML only). CI: GitHub Actions R-CMD-check matrix (macOS + ubuntu, R 4.2–4.5)
plus a release workflow. Docs site built with starlightr (`_starlightr.toml`).
(?) The release workflow `r-release.yml` and the NONMEM fixture contents under
`inst/extdata/models/` were only skimmed — re-verify anything relied on there.
